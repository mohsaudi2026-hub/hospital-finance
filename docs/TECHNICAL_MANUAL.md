# دليل المعمارية والمواصفات الفنية للنظام (Technical Architecture Manual)
## منصة تجميع البيانات المالية للمستشفيات والمنشآت الطبية — وزارة الصحة والسكان

---

## 1. نظرة عامة على النظام (System Overview)
تم تصميم وتطوير هذه المنصة خصيصاً لوزارة الصحة والسكان المصرية لتجميع وتدقيق وتوحيد البيانات المالية لكافة المستشفيات والمنشآت الطبية والنموذجية على مستوى الجمهورية، بما يشمل:
- الإيرادات الذاتية (8 مصادر رئيسية وفق اللائحة الرسمية).
- التجنيب والاستقطاعات القانونية (مستحقات العاملين وصندوق الأدوية).
- فواتير وأذون هيئة الشراء الموحد (أدوية ومستلزمات).
- عقود التشغيل والصيانة والأمن والنظافة والتغذية والسدادات الشهرية.
- منظومة التسويات المالية وسجل التدقيق والرقابة المالية الصارمة.

---

## 2. المكدس البرمجي المعتمد (Technology Stack)
- **Frontend Framework:** Next.js (App Router v16+ Turbopack) + React 19 + TypeScript.
- **Styling:** Vanilla Tailwind CSS مع نظام ألوان مستمد من الهوية البصرية الرسمية لوزارة الصحة المصرية (`#1E5AA8` الأزرق الحكومي، `#C8102E` الأحمر، `#FBF7EC` الكريمي الفاتح).
- **Backend & Database:** PostgreSQL via Supabase (Supabase Auth, Row Level Security, Pl/pgSQL Triggers).
- **Data Validation:** Zod — مخطط تحقق موحد بين الواجهة والباك إند لمنع تكرار المنطق.
- **Data Visualization:** Recharts لبناء الداشبوردات التنفيذية والتشغيلية المتقدمة.
- **Exporting:** jsPDF (توليد تقارير PDF الرسمية بترويسة الوزارة) + XLSX (تصدير جداول Excel التفصيلية).

## 3. هيكل قاعدة البيانات ومخطط الجداول (Database Schema)

### 3.1 جداول البنية الهيكلية والمصادقة
1. **`roles`**: يحتوي على الأدوار الخمسة الصارمة للمنظومة:
   - `super_admin`: صلاحية إدارة النظام بالكامل والمستشفيات والمستخدمين والمهل الوزارية.
   - `ministry_viewer`: استعراض كافة التقارير والداشبورد الوزاري والتنفيذي (قراءة فقط).
   - `hospital_admin`: إدارة مستخدمي المستشفى واعتماد الإغلاق الشهري وإجراء التسويات.
   - `hospital_data_entry`: إدخال القيود المالية وأذون الشراء وسداد العقود لمستشفاه فقط.
   - `hospital_viewer`: استعراض تقارير وإحصائيات مستشفاه فقط (قراءة فقط).
2. **`facilities`**: المنشآت الطبية والمستشفيات (تشمل كود المستشفى، الكود المؤسسي، المحافظة، والمديرية، وتصنيف المستشفيات النموذجية `is_model_hospital`).
3. **`profiles`**: بيانات المستخدمين الشخصية وحالة إجبار تغيير كلمة المرور الأولى `must_change_password`.
4. **`user_facility_roles`**: جدول الربط (Junction Table) لتحديد دور كل مستخدم والمنشأة التابع لها.
5. **`announcements`**: إدارة الإعلانات والتعليمات الوزارية التي تظهر في شاشة تسجيل الدخول.

### 3.2 الجداول المالية والتشغيلية
1. **`revenue_sources`**: بنود الإيرادات الـ 8 الرسمية.
2. **`revenue_entries`**: قيود مبالغ الإيرادات الشهرية المحصلة لكل منشأة ومصدر.
3. **`deductions`**: مبالغ التجنيب (مستحقات العاملين 40% / الأدوية والمستلزمات 60%).
4. **`procurement_orders`**: أذون تسليم هيئة الشراء الموحد المسعرة (أدوية ومستلزمات، خزانة/صندوق).
5. **`contracts`**: العقود الخدمية (أمن، نظافة، صيانة، أغذية مرضى، أغذية عاملين) وقيمها الإجمالية.
6. **`contract_payments`**: دفعات السداد الشهرية المسجلة لكل عقد.
7. **`monthly_closures`**: سجلات الإقفال والاعتماد النهائي للشهر المالي لكل منشأة لمنع التعديل المباشر.
8. **`monthly_deadlines`**: مواعيد المهل الوزارية المحددة للتسجيل وقفل النظام تلقائياً.
9. **`financial_adjustments`**: سجلات التسويات والتصحيحات المالية المعتمدة بعد الإقفال الشهري.
10. **`audit_log`**: سجل التدقيق المالي الشامل غير القابل للتعديل أو الحذف (`IMMUTABLE`).

## 4. سياسات الأمان والحماية (Security & RLS)
- **عزل البيانات على مستوى الصفوف (Row Level Security - RLS):** مفعل على 100% من الجداول.
- دالة التحقق المركزية:
  ```sql
  public.user_has_role_for_facility(target_facility_id uuid, allowed_roles text[])
  ```
  تضمن برمجياً عدم تمكن أي مستخدم من قراءة أو كتابة أي سجل خارج نطاق المنشأة المخصصة له.
- **حظر الحذف النهائي (No Hard Delete):** جميع الجداول المالية محمية برمجياً؛ لا توجد سياسة `DELETE` للمستخدمين العاديين، وأي تصحيح يتم عبر قيد تسوية.
- **تأمين المشاهد (Security Invoker Views):** كافة عروض التجميع (`monthly_facility_summary`, `annual_summary`, `quarterly_summary`) تم ضبطها بـ `security_invoker = true` لترث قيود RLS بدقة.

## 5. التريجرز والمنطق التلقائي (Database Triggers)
1. **`trg_lock_*`**: منع أي عملية إدخال أو تعديل مباشر على أي شهر مسجل في جدول `monthly_closures`.
2. **`generate_ref_number_*`**: توليد كود مرجعي فريد لكل معاملة مالية بصيغة:
   `[كود المنشأة]-[السنة]-[الشهر]-[تسلسل]` (مثال: `CAI01-2026-08-0001`).
3. **`generate_ref_number_adjustments`**: توليد أرقام مرجعية لسندات التسوية بصيغة `[كود المنشأة]-ADJ-[السنة]-[الشهر]-[تسلسل]`.
4. **`log_financial_audit`**: تسجيل فوري لأي عملية إنشاء أو تعديل أو تسوية في جدول `audit_log` متضمناً القيمة السابقة والجديدة وهوية المنفذ وتاريخ العملية بالملي ثانية.

## 6. مسارات واجهات المستخدم والمكونات (Application Architecture)

```
app/
├── (auth)/
│   └── login/                  # شاشة تسجيل الدخول الرسمية + لوحة الإعلانات
├── change-password/            # شاشة الإجبار على تغيير كلمة المرور
├── (dashboard)/
│   ├── layout.tsx              # القائمة الجانبية الموحدة وشريط الهوية
│   ├── dashboard/              # الداشبورد الوزاري والتشغيلي
│   ├── revenue/                # استمارة قيد الإيرادات والتسويات
│   ├── deductions/             # استمارة قيد التجنيب والاستقطاع
│   ├── procurement/            # أذون هيئة الشراء الموحد
│   ├── contracts/              # عقود المنشأة والسدادات
│   ├── reports/                # التقارير المجمعة والتصدير الرسمي (PDF/Excel)
│   └── admin/                  # لوحة إدارة المنشآت والمستخدمين والمهل والتدقيق
components/
├── ui/                         # مكونات التصميم الموحدة (FormField, FormSelect, StatCard...)
│   └── AdjustmentModal.tsx     # مودال إجراء التسويات المالية
lib/
├── constants.ts                # الثوابت والأدوار الرسمية
├── database.types.ts           # مخطط الأنواع الصارم المتوافق مع Supabase
└── utils/                      # دوال تنسيق العملة والتاريخ والسنة المالية المصرية
```

## 7. متطلبات بيئة التشغيل (Environment Variables)
يجب توفر المتغيرات التالية في ملف `.env.local` أو سيرفر الإنتاج:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
```
